# city-stroll

city-stroll 是给常驻本地的人做的周末逛吃规划小工具。很多时候周末想出门转转，翻半天小红书和大众点评，全是碎片化的帖子，越看越不知道去哪。

city-stroll 做的事情很简单：把全网公开的口碑翻一遍，「景点」和「美食」各拉出两份榜（近期热门 + 老牌经典），再根据你的出发地，按顺路原则排一条半天到一天的行程，连路上的通勤时间和饭点一并算好。

目前支持北京、上海、广州、深圳、成都、杭州、西安、武汉、南京、重庆 10 座城市。零运行时依赖，既可以装进 DeepSeek Harness（DSH）当插件用，也可以直接把 SKILL.md 丢进 Claude Code、Codex 这类 Agent 里跑。

## 核心功能

### 1. 两份榜单：近期热门 + 经典口碑

景点和美食分开拉榜，避免把网红快闪店和几十年老字号混在一起比：

- **近期热门**：最近风大、讨论度高的地方，跟着季节和活动走（比如 11 月看银杏赏秋、年底看灯光秀）。
- **经典口碑**：常年被本地人和游客反复提起的老去处，不太随时间大起大落。

每条推荐都会附上来源链接和置信度（高 / 中 / 低）。只有多个不同平台的来源同时提到，置信度才算「高」，单篇爆款笔记说了不算。

### 2. 不折腾的顺路行程

按你的出发地就近找点，景点之间用真实坐标算距离（最近邻顺路排序），尽量少走回头路。排出来的日程包含：

- 每段路的通勤方式和大概耗时（用内置地铁站坐标 + 直线距离估算）
- 每个地方建议待多久
- 饭点安排（按上午 / 下午自动穿插午饭或晚饭）
- 全程总耗时

### 3. 缺信息先追问，不瞎排

如果你只丢过来「成都」两个字，它不会硬编一套方案，而是先问你：「从哪出发？想逛半天还是一整天？」——给几个常见区域让你选，也可以自己填。关键信息问明白了再排路线。

## 怎么用

### 在 DeepSeek Harness（DSH）中使用

前置要求：有一个能跑的 DSH 环境，且宿主开启了联网检索（`ctx.web.search`）。插件本身不发网络请求，也不需要额外配 API Key 或装全局 Node 依赖。

#### 1. 安装

直接从 GitHub 装（推荐，不用折腾 npm）：

```text
install_bundle  https://github.com/InnmingWon/city-stroll/archive/refs/tags/v0.2.0.tar.gz
```

或者把仓库 clone 到本地按路径装：

```text
install_bundle  C:\path\to\city-stroll
```

也可以直接从 npm 装（已发 0.2.0）：

```text
install_bundle  city-stroll
```

#### 2. 启用

```text
set_bundle  city-stroll  enabled:true
```

#### 3. 开聊

装好后直接跟 Agent 提要求就行：

- 「帮我排一下明天上午在北京逛逛，加顿午饭，九点从知春路走」
- 「上海周末半日游，人民广场出发，想看展」
- 「成都待一天，带爸妈，挑轻松点的地方」

如果是代码里直接调工具（为了兼容老版本，工具名还叫 `xiaohongshu_guide`）：

```json
{
  "destination": "北京",
  "scope": "both",
  "duration": "半天",
  "origin": "知春路",
  "preference": "综合",
  "theme": "通用",
  "slot": "上午"
}
```

### 在 Claude Code / Codex 等 Agent 中使用

仓库根目录下有一份独立的 `SKILL.md`，不绑定 DSH。直接把它拷进 Claude Code、Codex 等工具的 skills 目录里就能用，交互逻辑和排程效果完全一样。

## 数据从哪来？

提前交个底，把数据来源和边界说清楚。

### 1. 公开搜索，不爬平台私域

小红书、大众点评、美团都没有开放接口，硬爬既不稳定也违反服务条款。所以插件的做法是：

- 借宿主的 `ctx.web.search` 做搜索引擎检索；
- 用 `site:xiaohongshu.com`、`site:dianping.com`、`site:bendibao.com` 加上「必吃榜」「热门」等词做定向搜索；
- 只读取搜索引擎已经公开收录的标题、摘要和链接，不登录、不抓包、不碰平台内部数据，也不缓存或转售任何内容。

### 2. 来源权重怎么算

搜出来的东西五花八门，插件会按域名分个档，决定谁的参考价值更大：

| 档位 | 来源举例 | 怎么用 |
| --- | --- | --- |
| 官方 | gov.cn（比如园林绿化局发的「多彩京秋」变色率） | 权威事实，权重最高 |
| 点评 | 大众点评、美团 | 看评分、评价基数、必吃榜 |
| 榜单 | 高德、百度、本地宝 | 看近期热度和本地活动资讯 |
| 社区 | 小红书、微博 | 看新鲜度、是不是正在排队或刚出圈 |
| 旅行 | 马蜂窝、携程 | 偏重经典打卡点和长线攻略 |
| 噪声 | 百科、知道、贴吧、B2B 网站 | 直接过滤，不参与排榜 |

### 3. 内置的本地字典（离线部分）

`data/<city>.json` 里是手动整理好的 10 城基础数据（每城大概 50 个核心 POI、20 多个枢纽地铁站），用来干三件事：

- 算距离：存了景点、餐厅和地铁站的经纬度，用来估算怎么走顺路；
- 合并同类项：内置了别名表，知道「香山」「北京香山公园」「香山红叶节」是同一个地方，防止重复霸榜；
- 认路：存了行政区和默认中心站，方便匹配你的出发地。

## 参数与配置

### 调用参数

| 参数 | 必填 | 可选值 | 说明 |
| --- | --- | --- | --- |
| `destination` | ✅ | 字符串 | 目的地或具体片区，比如 上海、杭州西湖、北京海淀。 |
| `scope` | | `both` / `attractions` / `food` | 查什么，默认 `both`（景点 + 美食）。 |
| `duration` | | `半天` / `全天` | 打算逛多久，默认 `半天`。 |
| `origin` | | 字符串 | 出发地或地铁站。不填默认取各城中心站（如北京知春路、上海人民广场、广州体育西路）。 |
| `preference` | | 综合 / 自然秋景 / 人文老城 / 文艺展览 / 美食探店 / 运动户外 | 偏好风格，默认 `综合`。 |
| `theme` | | 通用 / 情侣约会 / 朋友聚会 / 亲子遛娃 / 带父母 / 独自慢游 | 同行场景，默认 `通用`。选「带父母」或「亲子」会自动踢掉爬山、攀岩这类费体力的地方。 |
| `slot` | | 上午 / 下午 / 晚上 | 出发时段，默认 `上午`。选「晚上」默认 18:00 出发，同时过滤掉爬山、看红叶等只适合白天的去处。 |

### 插件配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `maxResults` | `8` | 每次定向检索最多拿几条结果（1–20）。 |
| `timeoutMs` | `120000` | 单次检索超时时间（10000–600000 ms）。 |
| `defaultOrigin` | `知春路` | 没匹配上任何城市数据时的保底出发地。 |

## 局限与实话实说

把丑话说在前面，免得预期太高：

- **榜单不是官方实时热搜**：所谓「热门」，是根据搜索结果里的发布时间、互动字眼和跨平台提及率估算出来的，不代表小红书或点评后台的真实流量。
- **通勤时间只是粗算**：路线是用内置坐标算直线距离（Haversine）再加最近邻贪心排出来的，只管「大致顺路」，真出门请打开高德或百度地图看实时路况。
- **偶尔会有脏数据**：因为全程没接大模型做二次清洗，纯靠规则提取，极少数情况下榜里可能会混进半句话的标题或繁体字噪声。
- **新店新线可能滞后**：内置的 POI 和地铁站是手动维护的，刚开业的网红店或新通车的地铁线可能还没收录进去。
- **搜不到就不硬凑**：热门榜只认公开搜索里真提到过的地方。如果某个冷门条件实在搜不出东西，会直接显示「暂无」，不会拿内置库里的数据硬充数。
