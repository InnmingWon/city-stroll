# city-stroll

城市漫步 · 一日逛吃规划。给常驻本地的城市人用的出游小工具：翻一遍小红书和全网的公开内容，把「美食」和「景点」各整理成两份榜，再按你的出发地排一条一天以内的行程，路上的时间和大概花销一并算上。

支持北京、上海、广州、深圳、成都、杭州、西安、武汉、南京、重庆 10 城。支持DeepSeek Harness（DSH）Cordis 插件或者skill下载，零运行时依赖。

---

## 它能干什么

### 1. 两份榜单：近期热门 + 经典口碑

景点、美食分开各出两份：

- **近期热门**：最近被讨论得多的，随季节和活动变化（比如 11 月的赏秋、年末的灯光秀）。
- **经典口碑**：经年累月被反复提到的老牌去处，不随时间大起大落。

每条都带来源链接和置信度（高 / 中 / 低）。置信度来自多个独立来源的交叉印证，不是单一帖子说了算。

### 2. 一天以内的行程

按你的出发地就近推荐，景点之间按真实坐标做「最近邻顺路」排序，减少折返。行程里给出：

- 每段通勤的路线和大概时长（内置地铁站坐标 + 直线距离粗算）
- 每个去处的建议停留时间
- 午餐 / 晚餐的安排（按时段自动区分）
- 全程大概几个小时

### 3. 信息不全时会先问

只给了「成都」两个字，它会先问一句：「你从哪出发？」，给你几个选项，也可以自己输入。出发地、时长、偏好这些关键信息补全之前，不硬排计划。

### 输出长什么样

```text
## 近期热门 · 景点
1. 香山公园 · 置信度：高
2. 西山国家森林公园 · 置信度：中
3. 前门大街 · 置信度：中

## 经典口碑 · 景点
1. 颐和园 · 置信度：中
2. 圆明园 · 置信度：中

## 行程（09:00 出发 · 约 4 小时）
09:00–09:40  知春路 → 颐和园（地铁 10 号线 → 西郊线，约 40 分钟）
09:40–11:25  颐和园（约 1 小时 45 分）
11:25–12:25  全聚德（午餐，约 1 小时）
```

## 你需要做什么

### 前置条件

- 一个可用的 **DeepSeek Harness（DSH）** 环境；
- 宿主能提供**联网检索**（即 `ctx.web.search`）。插件本身不联网，检索能力由 DSH 提供；
- 不需要 Node 全局依赖，也不需要任何 API Key。

### 安装

发布到 npm 后：

```text
install_bundle  city-stroll
```

本地开发（从路径）安装：

```text
install_bundle  C:\path\to\city-stroll
```

### 启用

```text
set_bundle  city-stroll  enabled:true
```

### 调用

装好之后，直接对 Agent 说人话就行，比如：

- 「帮我规划一下明天北京上午加中午饭，九点出发」
- 「上海周末半日游，从人民广场出发，想看展」
- 「成都一天，带父母，别太累」

也可以直接调工具（工具名保留为 `xiaohongshu_guide`，方便老用户无缝升级）：

```json
{
  "destination": "北京",
  "scope": "both",
  "duration": "半天",
  "origin": "知春路",
  "preference": "综合",
  "theme": "通用",
  "slot": "上午"
}
```

## 数据来源

说清楚这个插件的数据到底从哪来。

### 1. 检索渠道：宿主提供的全网搜索

插件不直接连小红书、大众点评、美团——这些平台没有开放接口，直接抓也违反它们的服务条款。实际做法是：

- 通过 DSH 宿主的 `ctx.web.search` 做**全网检索**；
- 检索词里带定向，比如 `site:xiaohongshu.com`、`site:dianping.com`、`site:meituan.com`、`site:bendibao.com`，以及「必吃榜」「热门榜」「排行榜」这类榜单词；
- 拿回来的是这些网站在搜索引擎里的**公开索引内容**（标题、摘要、链接），不是平台内部数据。

### 2. 来源分级

检索结果按域名分档，决定它在一份榜单里的话语权：

| 档位 | 来源举例 | 作用 |
| --- | --- | --- |
| 官方 | gov.cn（如园林绿化局「多彩京秋」彩叶变色率） | 事实性信号，权重最高 |
| 点评 | 大众点评、美团 | 评分、点评数、必吃榜 |
| 榜单 | 高德、百度、本地宝 | 热度与本地资讯 |
| 社区 | 小红书、微博 | 新鲜度、排队与出圈信号 |
| 旅行 | 马蜂窝、携程 | 经典与攻略 |
| 噪声 | 百科、知道、贴吧、B2B | 不参与排序 |

### 3. 内置数据（不联网的部分）

每座城市一份 `data/<city>.json`，人工整理，包含：

- **POI 坐标库**：景点和餐厅的名称、经纬度、类型（景点 / 美食）、最近地铁站；
- **地铁站坐标**：用于通勤估算；
- **别名表**：「香山公园」=「北京香山公园 / 香山 / 香山红叶节」，保证同一个地方不重复计数；
- **行政区名**：用于出发地匹配和追问选项。

10 城共 10 份数据文件，每城约 46–51 个 POI、20–25 个地铁站。

### 4. 不做什么

- 不登录、不抓取小红书 / 大众点评 / 美团的页面；
- 不缓存、不转售任何平台内容；
- 榜单排序是基于公开检索结果的**启发式估算**，不是平台官方热度。

## 参数

| 参数 | 必填 | 取值 | 说明 |
| --- | --- | --- | --- |
| `destination` | ✅ | 字符串 | 目的地或区域，例如「上海」「杭州西湖」「北京海淀」。 |
| `scope` | | `both` / `attractions` / `food` | 查询类别，默认 `both`。 |
| `duration` | | `半天` / `全天` | 出游时长，默认 `半天`。 |
| `origin` | | 字符串 | 出发地 / 地铁站，默认取该城市的中心地铁站（北京知春路 / 上海人民广场 / 广州体育西路 …）。 |
| `preference` | | 综合 / 自然秋景 / 人文老城 / 文艺展览 / 美食探店 / 运动户外 | 偏好风格，默认 `综合`。 |
| `theme` | | 通用 / 情侣约会 / 朋友聚会 / 亲子遛娃 / 带父母 / 独自慢游 | 同行人 / 场景，默认 `通用`。带父母、亲子遛娃会自动剔除登山、攀岩等体力消耗大的去处。 |
| `slot` | | 上午 / 下午 / 晚上 | 出游时段，默认 `上午`。晚上会按 18:00 出发，并筛掉爬山、赏红叶这类白天专属项。 |

## 配置

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `maxResults` | `8` | 每个检索桶返回的最大结果数（1–20）。 |
| `timeoutMs` | `120000` | 单次检索超时（10000–600000 ms）。 |
| `defaultOrigin` | `知春路` | 未命中任何城市数据时的兜底出发地。 |

## 原理简述

1. 按「热门 / 经典」两个桶构造多条定向检索，带 `site:` 限域和榜单词。
2. 对结果做来源域名分级，计算交叉验证置信度（多来源同时佐证才算「高」）。
3. 用内置 POI 别名表做实体归一化，把「香山」「北京香山公园」「香山红叶节」归到同一个地方。
4. 按偏好、主题、时段做过滤和加权，产出两份榜单。
5. 用内置坐标 + haversine + 最近邻贪心生成顺路行程与通勤估算。

## 限制与诚实说明

- 「热度」是基于检索结果、发布时间、互动量和关键词信号的**启发式估算**，不是小红书或大众点评的官方实时数据。
- 通勤和顺路是内置坐标 + 直线距离的**粗算**，不是精确导航，出行请以高德 / 百度地图为准。
- 没有 LLM 参与事实约束，个别标题可能残留噪声（句子型标题、繁体字、微博正文页等）。
- 内置 POI 库是人工整理的，可能滞后于新开的店和新修的地铁线。
- 热门榜只收录在公开检索里被真实提及的地点；如果某类内容搜不到，会诚实显示「暂无」，不会用兜底数据硬凑。
